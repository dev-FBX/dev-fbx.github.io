In 30 seconds

One click, one email, and no repeated sends.

Problem

Confirmations, document copies, receipt notices: people expect the email before they leave the page, and someone ends up sending it by hand.

Solution

A button on the portal that calls a Power Automate flow, with validation and a lock before sending, and the result shown on screen.

Impact
1 flow · 3 languages

The same flow answers in Portuguese, English and Spanish, and the same address gets at most one send per hour.

Taken from the flow itself on Oct 1, 2026.

Architecture

From click to Outlook, through two gates.

  1. 01

    The portal calls

    Power Pages triggers the flow with the site's own anti-forgery token. No flow address written in the JavaScript.

  2. 02

    The flow decides

    It normalizes the address and language, validates, and checks the last send. Any closed gate returns a message and sends nothing.

  3. 03

    Send and log

    Outlook sends the subject and HTML for the language; Dataverse records the send, which decides the next time.

The hard call

Two gates: validation and a 1-hour lock.

Sending email from a public site is easy. The hard part is not becoming a spam tool.

Gate 1: is the address valid?

  • First, the address is lowercased and trimmed, and the page language is reduced to pt, en or es.
  • An invalid address comes back with a message on screen. Nothing is sent.
  • The check lives in the flow, not in the button: disabling the button in the browser would stop no one.

Gate 2: was there a send in the last hour?

  • The flow looks in Dataverse for a send to the same address in the last hour.
  • If there was one, it returns the time when you can try again. Nothing is sent.
  • If there was not, it sends and updates the record: last send, language and counter.

What the two gates do not cover

The lock counts per address, not per visitor. It stops the same inbox from getting ten messages in a row, but it does not stop someone from typing another person's email. That is why the form is switched off for now: a security decision, not a bug. To open it to the public, a third gate is missing, such as confirming that whoever types the address actually owns it.

The flow answers back, it does not just run

The trigger is called by the portal itself and returns the result in the same call: sent, invalid address or please wait, with the time. The page shows what happened instead of pretending it worked.

Privacy: what is stored and why
  • What is stored: the address, the time of the last send, the language and how many times it has been sent. Nothing else.
  • The data serves a single purpose: preventing the same address from receiving repeated sends.
  • There is no mailing list, no bulk sending, and the address is not shared with anyone.
  • The record lives in the environment's Dataverse, under the same access rules as the rest of the platform.
  • The call to the flow is authenticated by the portal with the anti-forgery token; the flow's address is not written in the page's JavaScript.
  • A real deployment would also add a privacy notice on the screen itself and a defined retention period.
What the company needs to have in place
  • Whoever clicks: nothing. The visitor needs no license and no account.
  • The run: the cost sits with whoever owns the flow and the environment, not with the visitor. Exactly which license depends on the company's plan and is checked before proposing.
  • The mailbox: an Outlook.com or Microsoft 365 account connected to the flow. In a company, a service account, not a personal one.
  • The record: a Dataverse table, which comes with the environment.
From prototype to production, in five steps
  • Discovery: which message, to whom, triggered by what, and what happens when it does not arrive.
  • Service account: the official sender mailbox and the connection. It is the item that delays things most, and the one that depends least on code.
  • Content and languages: write the message with whoever owns the subject and review it in each language before switching it on.
  • Safeguards: the lock, address validation, ownership confirmation when the form is public, logging attempts and what to do when a send fails.
  • Measure: how many sends, how many blocks, how many failures. Without that, you cannot tell whether the flow helps or annoys.
Full technical sheet
  • Trigger: a Power Pages call with the portal's anti-forgery token.
  • Languages: subject and HTML for pt, en and es in a single flow action, indexed by language. A fourth language is a new key, not a cloned flow.
  • Message: about 20 KB of HTML per language, with tables, controlled width and inline styles, which is how you write email that Outlook does not break.
  • Sending: through the Outlook.com mailbox connected to the flow.
  • Last change: Sep 14, 2026.
